Depthcue 0.1 · editor remake · the hybrid

Automatic layout, with freedom when you want it

This is the recommended editor (option A with C's quick bar, then B's review) with the freedom of option D added. Blocks sit in automatic slots by default. Any block can be pinned, then moved, resized and commented on, the way you would in PowerPoint. The sketch below is the demo deck: click, drag, type and press keys in it.

The rule that keeps it safe

Blocks sit in slots by default

Whatever an agent writes lands in the layout, so its decks stay clean and checkable. A block stays in its slot until you pin it.

Pin a block to take control of it

Pinning gives that one block a position and size. Drag it, resize it, align it. One click, or P, puts it back in its slot.

The same checks apply everywhere

Overlap, text that does not fit and blocks outside the safe area are flagged on the slide and in the ribbon, with a one-click fix.

What pinning changes underneath

A pinned block gets an optional frame in the scene file, in percent of the 16 by 9 slide. Comments live in their own file so scene files stay clean in a pull request.

What it costs

Compared with option A alone

  • About twice the work: roughly 20 pull requests against about 10.
  • Schema 0.2: an optional frame on blocks, and a comments file. Old decks keep working.
  • The editor is 25 KB brotli today. I estimate the whole remake at 40 to 50 KB, against the 90 KB budget. The player reads a static frame, so scene change time should not move; the 50 ms budget is measured in every phase.

Risks and how they are handled

  • Two ways to place things can confuse. Pinned blocks are marked, and the ribbon offers Back to layout when a pin causes a problem.
  • An agent rewriting a scene. Frames are keyed by block id, so they survive. Removing a block drops its frame.
  • Other aspect ratios. Frames are percent of a 16 by 9 slide. A 4 by 3 slide would need its own frames, so that waits.

What the agent gets

  • It reads frames and comments through deck_get.
  • It can add a comment or reply, and clear a frame to send a block back to its slot.
  • Its edits still go through base_rev: a stale copy is refused, never merged.
